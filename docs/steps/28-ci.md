Permissão só de leitura, tempo máximo de 10 minutos, nenhum segredo. **As ações estão fixadas pelo hash do commit** (`actions/checkout` v7.0.1, `astral-sh/setup-uv` v10.3.2, as duas publicadas há mais de duas semanas), com o rótulo num comentário: um rótulo pode ser movido pelo dono da ação, o hash não (tema do P4).
- **[config/run.json](../../config/run.json):** contra o que a última medição foi feita. Hoje só `p2_tag: step-16`; modelos, juiz e hash do prompt do juiz ficam vazios até serem escolhidos (o `check-repo` só avisa).
- **[evals/consistency.py](../../evals/consistency.py):** `check_repo(root)` devolve problemas (o CI falha) e avisos (o CI segue):

  | # | Confere | Quando falha |
  |---|---|---|
  | 1 | privacidade | um arquivo versionado de texto tem sequência com formato de CPF/CNPJ (o número nunca é mostrado). Ficam de fora as pastas fora do git e o `uv.lock`, cujos hashes têm longas sequências de dígitos |
  | 2 | casos | caso inválido, sem `split`, ou sem `cases/_split_meta.json` com a semente |
  | 3 | anotações | histórico ambíguo (`v1` e `v01`), caso ausente, ou uma versão que o seu validador recusa |
  | 4 | vereditos do juiz | formato inválido |
  | 5 | conta do juiz | o TPR/TNR do relatório mais recente não bate com o recálculo a partir das anotações cegas e dos vereditos gravados |
  | 6 | amostra cega e rascunhos | anotação revisada sem rascunho; rascunho de trace cego sem a anotação cega; gabarito rascunhado sem caso |
  | 7 | limiar | um critério calibrado abaixo de `config/thresholds.json` (ausente: só aviso; decisão adiada até a primeira medição) |
  | 8 | antes e depois | `config/run.json` difere do cabeçalho do relatório mais recente: **"mudou prompt, modelo ou tag do P2: falta um relatório novo"** |

- **[evals/cli.py](../../evals/cli.py):** `python -m evals.cli` com `check-repo`, `scan-privacy`, `apply-splits`, `verify-gabarito`, `hash-prompts` e os comandos que repassam para os módulos (`dossier`, `annotate`, `sample`, `draft-gabarito`, `draft-annotation`). Nenhuma regra mora no `cli.py`.

**Limites do que o CI vê** (registrados também em D7):
- **Os traces ficam fora do git.** A validação das anotações usa um trace mínimo deduzido do nome (`<case_id>-<8 hex>`, `status: ok`, porque só se anota trace `ok`).
- **A ordem "anotação cega antes do rascunho"** não tem data para comparar: o CI confere a regra mais fraca (todo rascunho de trace cego tem a anotação cega `v1`). A ordem é garantida pelo rascunhador, que recusa antes de chamar o modelo.
- **A recontagem do juiz não conhece os casos `disputed`** que dependem dos traces; um relatório com casos disputados pode divergir. Documentado no módulo.
- **O relatório mais recente é o de nome mais alto:** os relatórios em `reports/` precisam de nome ordenável (por exemplo, a data no início).
- O CI não sabe se um relatório veio de uma rodada de verdade; essa proteção é a revisão humana.
